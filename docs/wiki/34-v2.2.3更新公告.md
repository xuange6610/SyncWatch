# v2.2.3 更新公告

v2.2.3 是基于 v2.2.0 正式版和未发布的 v2.2.1/v2.2.2 候选继续完成的修复版本。线上发布状态以 [GitHub Release v2.2.3](https://github.com/xuange6610/SyncWatch/releases/tag/v2.2.3) 为准：只有页面公开、API 恰有 26 个维护者资产并连同两个源码归档共显示 28 个文件时才算发布完成。

v2.2.2 Tag 已固定指向其候选合并提交但没有 Release，不能移动或复用。本轮只使用唯一发布工作分支 `release/v2.2.3` 和独立的 annotated Tag `v2.2.3`；原子工作流只有在全部源码、文档、测试和 26+2 成品门禁完成后才公开 Release 并设为 Latest。

## 本轮真实变化

- **穿透客户端真实 IP**：HTTP 与 Socket.IO 共用可信代理链解析。回环和服务器本机网卡地址默认可信；外置 Nginx、Docker、Caddy 或 frp 通过 `SYNCWATCH_TRUSTED_PROXIES` 或 `--trusted-proxies` 声明精确 IP/CIDR，命令行优先于环境变量。Node/Electron 与独立包启动器都已接入该参数，Compose 也会显式映射环境变量；`0.0.0.0/0` 和 `::/0` 被 fail-closed 忽略。XFF 从右向左剥离可信 hop，不可信直连提交的转发头会被忽略，恶意最左项不能覆盖真实客户端。不同公网 IP 的游客可同时在线，同一真实 IP 的第二个游客仍被阻止。
- **游客提示可编辑**：新增稳定键 `login.guestIpOccupied`，默认文字是“当前 IP 已有游客在线，请先退出后再进入”。超级管理员可在“服务器设置 → 统一界面文案”双击或集中编辑、导入、导出；保存后实时广播，后续服务端拒绝响应直接使用新文字。
- **手机退出入口**：点手机顶栏账号行会在功能菜单内展开账号子菜单，不再直接打开资料而隐藏退出。首行保留“退出登录，保留账号密码”和普通“退出登录”；前者退出并清除会话后把本次账号密码恢复到登录表单，后者不保留。账号入口使用 disclosure 语义，Escape 可关闭并恢复焦点；房主退出弹窗默认聚焦“只退出房间”，支持 Escape 取消和 Tab 焦点约束。
- **手机布局**：功能菜单保持覆盖层，不改变播放器主区域高度；390px 起使用三列，375px 等窄屏使用可滚动两列。账号子菜单为紧凑双列，Android 触控高度仍至少 48px。本轮未更换主题色板。
- **继承候选修复**：同步小说使用精确 UTF-16 `characterOffset` 权威锚点；网络波动采用顺序探测和迟滞；媒体用 8 MiB 有界 Range 与最多 5 次渐进恢复；新客户端默认原画；首次管理员改密、账号密码策略、头像单击/双击、桌面关闭弹窗高亮和统一界面文案隐私边界继续保留。
- **恢复状态闭环**：修复 Chromium 断网后已经继续播放、但未补发 `playing/canplay` 时媒体恢复键可能残留的问题。健康 `timeupdate` 会重建 3 秒稳定观察点，只有连续播放通过后才清空恢复状态。
- **版本与构建**：源码、Android `versionName=2.2.3` / `versionCode=20203`、Electron/macOS/Windows 构建名、下载名和发布清单统一升级到 v2.2.3。

## 验证与发布边界

- 新增可信代理回归，覆盖不可信伪造、本机 tunnel、可信 CIDR、多跳链、恶意最左项、IPv6、IPv4/IPv6 `/0` 拒绝，以及真实 HTTP 与 Socket.IO 登录/审计 IP 一致性；平台契约覆盖双入口参数、启动器转发和 Compose 映射。游客集成测试另覆盖不同 IP 并存、同 IP 拒绝、文案实时广播与持久化。
- 浏览器回归覆盖 390×844 三列、375×667 小屏滚动、48px 触控、两个退出流程和凭据保留。Chromium 移动视口不是物理 Android 真机，正式 APK 仍需安装、启动、登录、连接和退出验证。
- 媒体恢复专项回归覆盖缺失 `playing/canplay` 的 Chromium 事件序列；真实 Electron 烟测执行 45 秒断网、Socket.IO 重认证、Range 恢复、继续播放与恢复状态清空。
- v2.2.3 的 17 个 SyncWatch 应用包必须全部从最终 Tag 对应源码重建；Node.js 4 项和 cloudflared 5 项须核对官方来源、版本、平台/架构和 SHA-256。
- 根目录 `dist/` 必须恰好形成 26 个维护者资产和两个最终 Tag 源码归档；任何一项缺失、为空、版本/闭包/启动不符时都不得上传残缺集合或设为 Latest。
- v2.2.0 的 Tag、Release、资产和历史保持不变；v2.2.1/v2.2.2 没有 Release，不删除或改写已有 Tag。

完整发布说明见 [v2.2.3 发布说明](https://github.com/xuange6610/SyncWatch/blob/release/v2.2.3/docs/release-notes-v2.2.3.md)。第一次使用请以 `admin` / `admin888` 登录并立即改密；升级前停止服务并备份整个 `SyncWatch同步观影-Data/`。

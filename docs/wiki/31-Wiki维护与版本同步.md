# Wiki 维护与版本同步

本页是仓库 `docs/wiki/` 与 GitHub Wiki 的维护约定。每个版本完成代码、测试和发布后，都要把真实变化同步到 Wiki；不能只改版本号，也不能继续保留上一版本的“候选”“未发布”状态。

## 版本更新后的固定顺序

1. **以代码和运行证据为准**：先核对 `server/index.js`、`public/`、桌面/Android 入口、专项测试和当前 Release。旧截图、聊天记录和未验证的计划不能作为已实现功能。
2. **更新版本公告**：为新版本新增对应编号的 `NN-vX.Y.Z更新公告.md`，历史公告只纠正历史事实，不覆盖成新版本；公告只写从上一版本真实发生的变化，并列出未验证的平台或构建边界。
3. **更新操作教程**：涉及登录、房间、播放、文本阅读、上传、权限、部署或下载时，同步修改对应的 01-29 页面，说明入口、字段、结果、错误和恢复方式。
4. **保持镜像一致**：把仓库 `docs/wiki/` 中的 Markdown 原文完整同步到 GitHub Wiki，保留同名文件、`Home.md` 和 `_Sidebar.md`；不要只更新 GitHub Wiki 而遗漏仓库镜像。
5. **生成 Pages HTML**：主要 Markdown 教程修改后运行 `node scripts/build-document-guides.js`，检查生成的 HTML 页面能打开、链接不指向旧版本、移动端没有横向溢出。
6. **验证后再发布**：至少运行 `npm run test:repo`、相关专项测试和 `git diff --check`。发布资产、哈希、版本号与下载链接全部核对完成后，才能更新 Release 正文。

## v2.2.1 候选已记录的行为边界

### 超级管理员首次改密

- 使用账号密码登录内置 `admin` 后，首次改密向导直接要求填写“新密码”和“确认密码”，不再重复输入已经用于登录的当前密码。
- 可以选择“暂不更改/稍后处理”；系统保留提醒，完成改密前不要把默认密码用于公网部署。
- 本机免密管理会话没有密码认证凭据时，仍按服务端安全策略要求当前密码；普通账号的周期改密也继续校验当前密码。不要把这两种入口写成同一流程。
- 修改成功后，`admin` 账号和服务器管理员密码一起更新，旧会话按服务端返回结果处理。

### 同步小说与文本阅读

- 文本文件必须先被房间选中；服务器把当前 `fileId`、UTF-16 字符锚点 `characterOffset`、归一化阅读位置 `position`（0 到 1）、页码 `page`、更新时间和递增 `revision` 作为权威状态，旧客户端仍可使用 position/page 兼容字段。
- 房主或被授予播放/阅读控制权的成员滚动文本、输入页码或使用上一页/下一页时，客户端发送 `text-reading-update`；服务器校验文件属于当前房间且仍是当前选中文件后，广播 `text-reading-state`。
- 所有客户端（包括晚加入和断线重连后恢复的客户端）都应使用同一 `fileId` 和 `characterOffset` 定位文本：先用 Range 找到锚点所在行首，再按本地几何滚动；窗口 resize 后重新校准。不同屏幕尺寸可以有不同换行，但不能显示另一份文件、旧 revision 或停在旧位置。
- 没有控制权的成员只能查看同步位置，不能覆盖房主进度。切换文件、删除文件或清空画面会重置文本状态，避免旧小说进度串到新文件。

## 文本阅读发布验收

每次修改同步阅读代码或 UI 时，使用两个独立会话（房主 + 普通成员）完成以下记录：

1. 两个会话打开同一个已审核文本文件，确认文件名和 `fileId` 一致。
2. 房主滚动到中段并等待广播，成员的文本位置与页码跟随；再用页码输入和上一页/下一页各操作一次。
3. 暂停网络或关闭成员页面后恢复会话，确认恢复到最新 `revision`，而不是回到第一页或旧位置。
4. 房主切换另一份文本、视频或清空画面，确认所有客户端清除旧文本位置；无控制权成员尝试滚动时不得改写房间状态。
5. 将桌面视口切换到 Android 390×844 仿真视口，确认字符锚点所在首段文本不变；v2.2.1 源码候选的 `text-reader.test.js` 与 `browser-ui-smoke.js` 包含该检查，最终结果以本次候选门禁日志为准。这是 Chromium 移动仿真，真实手机设备尚未验证。
6. 在桌面和移动视口各截一张脱敏证据，记录版本、浏览器/客户端、房间号（脱敏）、文件名（脱敏）和结果。没有真实设备证据时写“未验证”，不要写“所有设备已通过”。

## 页面与证据维护

- 截图必须来自当前代码和当前版本，删除真实姓名、邮箱、IP、令牌、房间链接和私人媒体名称；同一张旧截图不能冒充多个管理模块。
- 版本公告中的下载链接必须带 `vX.Y.Z`，并与 Release API 中真实存在的资产一致。GitHub Pages 只展示文档，不能描述成可运行的服务器。
- 发现代码、Wiki、HTML、README 或 Release 互相矛盾时，先标记“待核实”，修正代码/证据后再下结论；不要为了通过检查删除未验证说明。

## Platform

web

## Users

- 想和朋友、家人或小型团队远程同步观影的普通用户。
- 希望把服务和数据保存在自己设备上的房主或服务器管理员。
- 需要通过 Windows、Android 或浏览器加入房间的成员。
- GitHub 仓库文档与展示站优先照顾第一次接触 Node.js、Electron 和自托管服务的新手。

## Product Purpose

SyncWatch同步观影是一套开源、自托管的多人同步观影与实时协作系统。房主启动服务器并创建房间，成员通过客户端或浏览器加入；系统同步播放、暂停、进度、倍速等状态，并提供聊天、弹幕、语音、屏幕共享、媒体管理和服务器管理能力。

成功意味着新手能根据文档完成启动、连接和基础安全配置，成员能稳定加入同一房间，房主能掌握自己的媒体与运行数据。

## Positioning

产品将同步观影、跨端连接、本机数据目录和可选的临时公网访问放在同一套可自行部署的软件中；它不是由第三方代管媒体与账号的在线影视平台。

## Operating Context

- 房主在 Windows、Linux 或受支持的 Android 设备上启动服务。
- 局域网成员使用内网地址连接；跨网络成员可使用 Cloudflare Tunnel 或自有 HTTPS 反向代理。
- 服务器媒体、账号、设置和密钥保存在 `SyncWatch同步观影-Data/`，迁移前需要停止服务并完整备份。
- GitHub Pages 仅用于产品展示、截图、下载入口和新手导览；它不能运行 Node.js、WebSocket、文件上传或 cloudflared。

## Capabilities and Constraints

- 支持同步播放、媒体库、多房间、聊天、弹幕、语音、屏幕与网页共享、成员管理、媒体处理、数据备份及可配置的 AI 中转。
- 当前新版本支持 Windows、Web 与 Android；v2.3.1 起不再提供新的 macOS 构建，历史 Release 仍保留。
- 公网访问需要网络连接；临时公网地址由第三方 Cloudflare Tunnel 提供，不承诺固定域名或长期可用。
- 应用 UI、文档和发布标题使用完整名称 `SyncWatch同步观影`。
- GitHub 仓库 slug 保留为 `SyncWatch`，因为仓库地址和既有链接需要稳定。
- 已发布的包名、协议头、Java/JNI 类路径和旧数据目录名属于兼容标识，不作为面向用户的作者姓名展示，不在无迁移方案时修改。

## Product Principles

1. 先让新手完成一次可用连接，再解释高级部署选项。
2. 所有下载与功能声明必须对应真实存在且经过验证的文件或代码路径。
3. 静态展示、体验版和完整服务的能力边界必须清楚区分。
4. 默认保护账号、密钥、IP、聊天记录、媒体文件名和个人信息。
5. 兼容性优先于无意义的全量重命名。

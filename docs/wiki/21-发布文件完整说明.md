# 发布文件完整说明

v2.3.1 已完成最终 Tag、成品和 Release API 核验并公开为 Latest；清单为 8 个上传资产，加 GitHub 自动生成的两个源码归档，共 10 个可见文件。下载前仍应核对文件名里的版本号和角色。

## 文件分类

| 文件 | 角色 | 适合谁 | 作用 |
| --- | --- | --- | --- |
| `SyncWatch-Experience-Client-Portable-v版本-x64.exe` | 客户端 | Windows 普通成员 | 连接已有服务器 |
| `SyncWatch-v版本-Full-Offline-Portable-x64.exe` | 服务器 | Windows 房主 | 双击启动服务器，内含离线资源 |
| `SyncWatch-Android-v版本-universal.apk` | 客户端 | Android 用户 | 加入房间，支持设备可运行手机服务器 |
| `node-v24.19.0-x64.msi` / `arm64.msi` | 服务器环境 | 源码或独立服务器用户 | 安装 Node.js 与 npm |
| `cloudflared-windows-x64.exe` / 两个 Windows MSI | 服务器工具 | 需要公网访问的 Windows 用户 | 开启 Cloudflare Tunnel |

当前新版本不构建或上传 macOS、标准版和完整安装版。历史 Release 不会被删除。

## 选择流程

1. 房主下载 Windows 完整便携版。
2. 成员下载 Windows 体验版、Android APK，或直接使用浏览器。
3. 源码部署先安装 Node.js，再执行 `npm ci` 和 `npm start`。
4. 公网访问先启动服务器，再按 [运行环境教程](23-运行环境完整教程) 配置 cloudflared。

## 下载后校验

Windows 使用：

```powershell
Get-FileHash .\SyncWatch-v2.3.1-Full-Offline-Portable-x64.exe -Algorithm SHA256
```

哈希、大小或版本不对时重新下载，不要给旧文件改名。

## 发布门禁

所有上传文件都必须来自当前 Tag 的真实构建或已核验的官方分发。根目录 `dist/` 需恰好有 10 个文件（8 个上传资产加两个源码归档），并完成大小、SHA-256、平台和启动流程检查后才能发布。

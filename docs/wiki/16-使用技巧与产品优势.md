# SyncWatch同步观影 使用技巧与优势

## 推荐使用顺序

1. 先在同一个 Wi-Fi 内启动服务器和两台客户端，完成登录、创建房间、上传短视频和同步播放。
2. 给管理员设置独立强密码，给正式房间设置房间密码；普通成员使用普通账户，不共享管理员账号。
3. 确认媒体、聊天和权限正常后，再开启 Cloudflare Tunnel 或自己的 HTTPS 反向代理。
4. 第一次迁移或升级前停止服务，完整备份 `SyncWatch同步观影-Data/`，新版本启动后检查房间、媒体和密钥。

## 实用技巧

- **降低排错复杂度**：出现问题时先切回局域网，确认基础功能后再判断是公网、代理还是权限问题。
- **控制播放冲突**：观看时只让房主或一名可信成员拥有控制权，其他成员使用聊天反馈问题。
- **选择媒体版本**：原画保留最高质量；浏览器兼容版本适合编码复杂或设备性能较弱的成员。
- **管理大文件**：上传前检查磁盘空间，使用有线或稳定 Wi-Fi；转码期间不要关闭服务器。
- **保护日志**：导出日志前删除 IP、邮箱、令牌、媒体名称和聊天正文，保留时间、事件类型和错误码即可。
- **设置邮件**：使用 QQ 等服务商的应用专用授权码，测试成功后不要把授权码写入 README、Issue 或截图。
- **Android 省电**：手机作为服务器时关闭电池优化，保持前台服务通知，避免系统杀掉 Node.js Mobile。
- **公网分享**：只把临时地址发给可信成员，不要把带管理员权限的链接放到公开群组。

## 主要优势

### 自托管和隐私边界清晰

账号、房间、媒体、聊天和配置默认保存在自己的设备。GitHub Pages 只做静态展示，不会代替你的服务器保存数据。

### 一套房间，多端接入

Windows、Android 和现代浏览器共用同一套网页业务与 Socket.IO 房间状态，成员不必安装相同设备类型的客户端。

### 同步播放不依赖单一播放器

服务器广播播放状态、时间和版本，客户端按延迟和缓冲进行校正；支持播放、暂停、进度、倍速、字幕、聊天和公告协作。

### 从轻量到完整部署

可以使用 Windows 完整 EXE、Android 手机服务器、独立 Node.js 服务或 Docker。需要长期运行时再接入固定 HTTPS 反向代理。

### 管理、审计和备份一体化

房间、成员、权限、申请、邮件、日志、Tunnel 和数据导入导出集中在管理中心，敏感操作有权限检查和操作记录。

### 开源可审查、可共同维护

Apache-2.0 允许依法使用、修改和再发布；贡献者通过 Fork、分支和 Pull Request 协作，`main` 经过自动测试与维护者审核后才更新。

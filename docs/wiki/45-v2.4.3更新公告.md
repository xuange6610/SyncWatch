# v2.4.3 更新公告

SyncWatch同步观影 v2.4.3 针对 NAT 转发和反向代理下的视频播放失败进行了修复。

- 媒体 Range 响应移除 `Content-Encoding: identity`，避免部分 NAT/代理把无压缩媒体误判成未知压缩编码并返回 502 或重置连接。
- 媒体文件流先等待文件描述符成功打开；挂载、权限或文件句柄异常会返回可诊断 HTTP 错误，不再由 `pipeline` 把响应重置为 `ECONNRESET`。
- 增加 `X-Accel-Buffering: no`，让 Nginx/Caddy 等常见反代直接转发媒体流；继续提供 `video/*` MIME、Range 和正确长度。
- 保留 MP4、AVI、MOV、MKV、FLV、WMV、RM/RMVB、3GP、M4V、ASF/ASX、DAT、VOB、TS、WebM、MPEG/MPG、DivX/XviD、ProRes、AV1、H.264/H.265 和 VP9 上传分类与兼容转码。
- 增加媒体响应头回归测试，并在大文件 Range 中止、上传分类、FFmpeg 兼容版和公网恢复路径上完成回归。

公网端口转发仍需要把 TCP `20311` 完整映射到 SyncWatch 服务器，并允许持续的 HTTP Range 请求。页面、Socket.IO 和缩略图可用而视频仍失败时，请优先检查 NAT 服务的单连接时长、流量/响应大小限制和是否改写了 Range/Content-Length；这些限制无法由应用代码绕过。

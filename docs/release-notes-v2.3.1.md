# SyncWatch同步观影 v2.3.1 发布说明

## 本次修复

- 共享画面默认走 Electron 的原生捕获回调，Windows 系统声音通过 loopback 音轨与画面一起发送；共享设置继续默认请求当前设备原生分辨率、最高刷新率和极致画质。
- 共享音频优先使用 WebRTC Opus 直连，连接尚未建立时才延迟启用 PCM 兼容回退；接收端增加 120ms 抖动缓冲，Opus 固定 48kHz、20ms 帧和 FEC，减少放歌时断续。
- 共享音频状态条继续实时显示共享者、音频文件/媒体标题和进程名，停止、断线和切房时即时清理，并动态避让进度条。
- 修复 Android 强制停止后数据目录锁因 PID 复用而永久阻塞的问题；过期心跳锁会安全回收，并把旧版本遗留的 5000 端口一次迁移到 20311。
- 修复桌面中等宽度顶栏的按钮拥挤：操作区自适应网格、可横向滚动，窄桌面隐藏次要状态列，菜单面板保持可读宽度，移动端仍保持完整下拉列表和触控尺寸。
- Android WebView、嵌入式手机服务器和下载入口统一更新到 2.3.1，避免升级后仍引用旧 APK 名称或旧端口。

## 验证

最终 Tag 已真实重建，8 个维护者资产已进入公开 Release；本说明记录最终修复、验证和使用边界。

- 本版本 Release 目标为 8 个维护者资产（Windows 体验版/完整便携版、Android APK、Node.js MSI 与 cloudflared 工具），加 GitHub 自动生成的两个源码归档。
- 前端、共享音频桥接、服务端锁恢复、默认端口、平台契约和 Android 源码包检查通过。
- 浏览器冒烟覆盖桌面 1365/1920、手机 390×844、375×667、812×375，包含登录、顶栏菜单、共享设置、音频状态、全屏、AI、管理中心和下载中心截图。
- Windows Electron loopback 音频 smoke 在 Windows runner 上执行；无音频设备的托管 runner 仅允许保留视频链验证并明确标记跳过音频硬件断言。

## 使用边界

实际画面帧率、分辨率和音频连续性仍受操作系统捕获能力、浏览器自动播放策略、编码器和网络路径影响；“最高”表示向当前设备能力请求上限，不承诺物理 0 延迟。

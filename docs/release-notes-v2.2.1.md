## 从 v2.2.0 到 v2.2.1 的更新公告

下面只记录当前源码相对 v2.2.0 的真实变化。构建、测试、真机和线上状态没有证据时保留“待验证”，不会因文件名或文档已更新就写成已经发布。

### 小说与文本同步

- 房间权威阅读状态新增 UTF-16 `characterOffset` 字符锚点，并继续保存 `fileId`、归一化 `position`、页码、更新时间和递增 `revision`。
- 房主或拥有控制权的成员通过 `text-reading-update` 提交阅读位置；服务端校验当前房间、当前文件和控制权限后广播 `text-reading-state`。无控制权成员只能跟随。
- 客户端始终保留服务端下发的精确 UTF-16 字符锚点，本地 Range 几何只负责把锚点字符所在的视觉行滚动到顶部，不能用桌面或手机各自的换行行首改写权威偏移。窗口尺寸变化后会重新校准；不同视口可以有不同像素位置和行首，但必须保持同一文件、同一 revision、同一逻辑锚点和同一锚点字符。
- 晚加入与断线重连会恢复最新权威状态；旧 revision、旧文件的延迟事件会被忽略。切换或删除当前文本会清除旧阅读状态，避免进度串到另一部小说。

### 网络状态与播放恢复

- 顶栏“网络波动”改为由 Socket.IO 控制通道的连续探测决定，不再把一次 RTT 尖峰、视频 `waiting/stalled` 或成员短暂重连直接放大成全房间故障。
- 客户端每 4 秒最多发起一个探测；连续 3 次延迟超过 500 毫秒或超时才进入 `unstable`，连续 2 次健康样本后恢复。真正的本机 socket 断开继续明确显示“连接中断”，不会被迟滞逻辑掩盖。
- 探测使用递增 sequence、连接 epoch 和单一在途请求，服务端忽略乱序结果，质量遥测使用 volatile 发送，避免旧结果在重连或切房后覆盖新连接状态。
- 视频缓冲和控制通道质量保持两条独立路径：媒体连续 12 秒无播放时间/缓冲增长时仍进入最多 3 次有限恢复；活动 HTTP Range 传输不应阻塞 Socket.IO 探测。此修复减少误报，不承诺消除家庭上行、Tunnel、VPN/TUN 或运营商链路的真实波动。

### 登录、账户与权限

- 使用账号密码完成认证的内置 `admin` 首次改密时，向导直接填写新密码和确认密码，不再重复输入刚用于登录的当前密码；“暂不更改/稍后处理”仍保留。
- 免重复校验能力由服务端按“账号密码已认证且仍处于首次初始化”一次性签发；新密码仍需至少 8 位且不能复用 `admin888`，成功后能力立即撤销。本机免密管理会话没有密码认证凭据，因此仍需当前密码；普通账号周期改密也继续校验当前密码，不能借首次初始化字段绕过。
- 新注册账号和普通密码默认不限制业务字符类型或字符数，允许空格、标点、符号和 Unicode；服务端仍保留用户名 1024 UTF-8 字节、密码 4096 UTF-8 字节的异常请求防护上限。
- 管理员可以在服务器设置中显式启用字符集及字符数范围；同一策略用于注册、改密、找回密码和游客转正式账号，并在重启后保留。

### 播放、桌面与界面文案

- 新客户端默认选择原画；局域网、反向代理和 Cloudflare Tunnel 不再根据连接方式自动降为流畅版。用户仍可手动选择自动或流畅版，既有个人选择继续保留。
- 成员头像保留单击打开资料，桌面双击或触摸端快速双击打开大图预览。单击等待双击判定后执行；如果期间成员状态更新重建列表，会按账号重新定位当前头像控件，避免旧节点断开导致单击失效，也避免双击先误开成员名片。
- 桌面关闭选择窗不再固定只高亮“最小化到托盘”；鼠标悬停或键盘聚焦到哪个操作，哪个操作使用同一套高亮背景、边框和可读文字颜色。
- 服务器设置新增“统一界面文案”：超级管理员可编辑显式稳定键及自动发现的固定界面文字、按钮和受控属性；界面内支持双击条目编辑，也支持设置页集中编辑、JSON 导入/导出和恢复默认。
- 文案修改通过服务端 `ui-copy-state` 实时同步给在线客户端。自动目录排除影片名、账号、IP、Toast 和动态对话正文等运行数据；服务端最多接受 5000 个受控 key、每项 240 个字符和 2 MB 导入 JSON，并拒绝未知 key、HTML、脚本、可执行协议、选择器和 DOM 路径。

## 与 v2.2.0 保持不变

- 房间创建/加入、播放同步、聊天/私聊/弹幕、语音、屏幕共享、好友、邮件、上传审核、备份恢复和管理中心 11 个模块继续保留。
- 默认数据目录仍为 `SyncWatch同步观影-Data/`；升级前必须停止服务器并备份整个目录，同一数据目录仍只允许一个实例写入。
- Windows 体验版只连接已有服务器；标准版用于本机开服；完整安装版与完整便携版提供同等的跨平台离线下载资源。
- GitHub Pages 仍是静态展示与教程站，不能运行 Node.js、Socket.IO、上传、AI 中转或 Cloudflare Tunnel。
- 项目继续采用 Apache-2.0，公开作者署名为 `xuan`；发布包不得包含账号、聊天记录、真实 IP、令牌、签名密钥或运行数据。

## 普通用户怎么选

- 只加入别人服务器：Windows 体验版、Android APK、macOS 客户端或浏览器。
- Windows 自己开房：标准服务器便携版；需要跨平台离线下载中心时选择完整安装版或完整便携版。
- Mac 自己开房：按 Intel x64 或 Apple Silicon arm64 选择服务器版；需要离线下载中心时选择完整离线版。
- 源码或独立服务器：安装官方 Node.js 22+；正式桌面包已内置运行时，无需重复安装。
- v2.2.1 资产未完成前请继续使用 [v2.2.0 正式版](https://github.com/xuange6610/SyncWatch/releases/tag/v2.2.0)，不要把候选文件名当成下载链接。

## 跨平台完整套装

完整离线包应把同一最终 Tag 真实构建并验证的 Windows 客户端、Android APK、macOS x64/arm64 客户端与服务器 ZIP 放入房主端下载中心。缺少任一平台文件时，Windows/macOS 完整包构建必须失败，不能嵌入旧版本、空文件或占位文件继续发布。

## 一键运行包含什么

Windows 正式服务器包应内置 Electron/Node.js 运行时、应用前后端、生产依赖、Socket.IO、FFmpeg、FFprobe 和 Windows cloudflared。启动时初始化数据目录、检查端口、启动 HTTP/WebSocket 服务并显示局域网地址；实际包含内容必须由最终成品闭包测试证明。

## macOS

v2.2.1 计划提供客户端、服务器和完整离线版各自的 Intel x64 与 Apple Silicon arm64 DMG/ZIP，共 12 项。它们必须由真实 macOS runner 从最终 Tag 构建；当前尚未生成或上传，不能用 Windows 产物、改名旧包或只更新应用显示版本替代。签名与公证状态应以最终构建记录和 Release 正文为准。

## 架构支持边界

- Windows 桌面：x64；当前不承诺未经完整验证的 32 位桌面组合。
- Android 通用 APK：计划继续包含 `armeabi-v7a`、`arm64-v8a`、`x86_64`，最终以 APK 解包和签名检查为准。
- macOS：Intel x64 与 Apple Silicon arm64；现代 Electron/macOS 不提供 32 位桌面包。
- 独立服务器：以 Node.js 22+ 对目标系统和架构的官方支持为准。
- Android 本机不能直接运行桌面版 cloudflared；手机跨网访问应连接已开启 HTTPS/Tunnel 的 Windows、macOS、Linux 或云服务器。

## cloudflared 独立工具

计划沿用 Windows x64 EXE、Windows x64/x86 MSI、macOS x64/arm64 二进制共 5 项。它们是 Cloudflare 官方工具，用于手工 Tunnel 与诊断，不是 SyncWatch 启动程序。正式上传前须重新核对 [Cloudflare 官方 Release](https://github.com/cloudflare/cloudflared/releases/latest) 的版本、平台、架构、大小和 SHA-256。

## Node.js 官方环境包

计划提供 Windows x64/ARM64 MSI、macOS x64 PKG 和 macOS arm64 tar.gz 共 4 项，供源码和独立服务器使用。它们是 Node.js 官方分发文件，不由 SyncWatch 源码生成；正式桌面包已内置运行时。正式上传前须重新核对 [Node.js 官方下载](https://nodejs.org/en/download) 的版本、平台、架构、大小和 SHA-256。

## 首次启动、升级与安全

1. 首次启动使用 `admin` / `admin888` 登录并立即修改默认密码；公网部署前先完成局域网连接测试。
2. 升级前停止旧服务器并备份整个 `SyncWatch同步观影-Data/`，不要只复制 `config.json`。
3. 不公开数据目录、SMTP 密钥、Tunnel 令牌、签名文件、聊天记录、真实 IP 或带权限的房间链接。
4. v2.2.1 尚未完成发布验收；在 Tag、资产、哈希、启动和在线链接全部验证前，不要用候选源码覆盖生产环境。

## 已知限制

1. 当前没有小米 14 / HyperOS 真机安装、后台保活、登录和屏幕共享证据。
2. 不同视口的文字换行、视觉行首和像素滚动值可以不同；同步目标是同一文件、最新 revision、精确逻辑 `characterOffset` 与同一锚点字符，不是强制相同像素坐标。
3. macOS 最终签名、公证和 Gatekeeper 行为要等真实 runner 成品完成后确认。
4. Cloudflare Quick Tunnel、家庭上行和 VPN/TUN/Fake-IP 网络没有固定 SLA；默认原画会增加带宽需求，弱网用户应手动选择流畅版。

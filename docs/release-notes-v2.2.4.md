和朋友、家人、情侣远程一起看电影。v2.2.4 在 v2.2.3 的稳定基线上继续完善全屏观影、账户级简洁模式、地址隐私、房间迁移、播放队列、登录解限、权限和跨端更新检查。

## 从 v2.2.3 到 v2.2.4 的更新公告

下面只记录本轮真实修改；长期保留但没有变化的能力放在后续使用说明中，不冒充本次新增。

### 全屏、弹幕与边看边聊

- 修复双击视频进入全屏后弹幕层被覆盖的问题。原生全屏和应用内全屏都会把弹幕保持在媒体上层。
- 全屏双击只调出“边看边聊”和控制层，不再把浏览器原生的播放/暂停事件广播给房间；双击手势期间的单击播放事件会被延迟消歧并按房间权威状态回滚。
- 全屏期间禁止普通 Toast、通告、授权提示、系统弹窗和应用对话框，只保留弹幕，以及用户主动调出的边看边聊界面。待确认的清晰度申请在退出全屏后再显示。
- `F12` 可切换观影画面全屏。两种全屏入口和退出路径共用恢复逻辑，修复浏览器缩放、低分辨率或低高度视口下“展开聊天”和顶部操作不可见的问题。
- 全屏聊天卡片不再使用会溢出窄视口的固定最小宽度；低高度时操作区可滚动，退出全屏和聊天入口始终可达。

### 简洁模式、聊天与弹幕外观

- 房间顶栏新增账户级“简洁模式”。开启后切换到更紧凑的观影界面，隐藏片库、成员、公告和非核心控制，只保留媒体、基础播放、进度、音量、全屏等必要功能。
- 简洁模式停止接收普通通知，仅保留成员进入/退出房间和进度拖动/跳转通知；设置保存在服务器账号资料中，并实时应用到该账号的其他客户端。
- 聊天区新增“仅显示聊天内容”，可过滤系统通报和公告，同时保留用户聊天；这是账户级偏好，不影响房间其他成员。
- 弹幕输入旁新增外观设置，可按账号调整接收端弹幕颜色和字号、即时预览或恢复默认；服务器保存后在该账号的客户端同步。

### 公网地址与隐私

- 普通 Electron 客户端、Android WebView 和浏览器客户端不再显示“局域网服务”IP；拥有超级管理员权限也不会因此暴露服务器内网地址。
- 通过 Tunnel 或公网域名访问时，状态和分享只使用当前已验证的公网 Origin 或服务器配置的公网根地址，并只展示一个地址。
- 普通客户端没有可信公网地址时按 fail-closed 处理：分享入口保持空置，不回退到 LAN IP。只有真实服务器应用窗口可以显示局域网服务地址。
- 桌面服务器、桌面客户端和 Android 分别注入不可混淆的运行角色标记，避免把远程客户端误判成服务器主机。

### 账户、登录与系统通知

- 取消“普通账号被授予超级管理员后必须重置密码”的限制；首次强制修改默认密码只针对内置 `admin`。
- 登录频率触发“登录次数过多”后，错误窗提供申请清除限制入口；服务器管理员可即时同意或拒绝，未及时处理的申请会保留在用户申请中心。
- 管理员批准后会清除对应来源和账号的登录失败窗口，申请人无需等待原限流时间结束即可再次登录；处理结果会回传给申请端并持久记录。
- “当前设备无法定位”等敏感系统状态只发送给内置 `admin` 的受信管理会话；普通成员以及后来被赋予超级管理员的账号都不会收到。普通房间通知按用户的简洁模式和聊天过滤设置继续分流。
- 注册受限申请可填写所需账号数量；申请仍待处理时，提交设备可按数量部分撤回或全部撤回。用户申请中心显示总数、剩余数和状态，内置 `admin` 可单条或批量删除记录，普通超级管理员不能删除。
- 账户与注册管理只显示密码未设置/已安全设置、待修改、过期和最近更新时间，服务端不返回明文、密码哈希或可逆凭据。“重置为默认密码”会撤销该账号现有会话，并要求用户按安全流程重新修改。

### 房间复制、迁移和媒体文件

- 房主可向另一个房间的房主发起“复制房间数据与配置”申请。来源房主同意后，系统为申请方创建副本并复制房间配置、权限组、队列、播放模式和媒体文件。
- 超级管理员可选择来源房间和目标房间执行一键迁移覆盖；目标房间 ID 和所有者保持不变，业务配置与媒体内容由来源房间替换。
- 媒体复制采用受控的服务器文件路径和新文件 ID，不把来源房间的绝对路径直接交给客户端；失败会回滚临时副本，不留下半迁移状态。
- 申请、批准、拒绝和管理员迁移均写入操作记录，并通过房间和申请中心事件更新有关用户。

### 播放权限、清晰度、片头片尾与队列

- “成员与权限组”新增独立的快进/拖动权限 `seek`。旧权限数据默认跟随原播放控制权，新配置可允许拖动但不允许播放/暂停。
- 有播放控制权限的成员可以调整倍速；倍速写入房间权威播放状态并实时同步给所有成员，而不是只修改本地播放器。
- 服务器管理员或房主可向指定用户申请切换原画、自动或流畅清晰度；用户确认后只调整自己的播放源并回传处理结果，不强行覆盖客户端选择。
- 房间工具新增片头片尾设置，房主或具备房间管理权限的成员可设定自动跳过的片头秒数和片尾秒数；选择新影片和队列自动续播都会应用同一设置。
- 片库支持批量选择已审核媒体并一次加入播放队列，队列支持全选和批量删除。批量加入后继续使用房间当前的顺序、循环、单曲或随机播放模式。

### 检查更新与跨端一致性

- 检查更新改为读取稳定 Release 接口，兼容 `tag_name`、`tagName` 和 `version` 字段，并使用 `no-store`/`no-cache` 避免缓存把新版本误判成旧版本。
- 服务端更新检查加入超时、ETag 复验、短期缓存和网络失败回退。缓存结果会明确标注来源和是否过期，不把无效版本响应显示成“已是最新”。
- Windows 服务器、Windows 客户端、Android 和浏览器共用同一地址隐私、Release 版本比较和更新入口语义。

### 网页 URL、关于和独立控制台

- “同步网址（各端独立浏览）”由服务端校验 HTTP/HTTPS 地址并持久化 URL、标题、操作者和 revision；晚加入、重连或换设备后恢复同一房间权威地址。
- 各客户端在 sandbox iframe 中独立加载目标网页，登录 Cookie、地域、广告/A-B 测试、CSP、`X-Frame-Options` 和跨域脚本仍由目标站控制；SyncWatch 不绕过安全策略，也不承诺跨域点击、滚动或第三方播放器状态一致。需要同一像素画面与主持人操作时使用“实时共享网页画面”捕获标签页/窗口。
- Web 顶栏新增“关于”，与 Electron“帮助”菜单统一展示产品、作者 `xuan`、Apache-2.0、GitHub 项目主页和 Wiki canonical 地址，避免客户端继续打开旧仓库或旧文档。
- 纯 Node.js 独立服务端明确为无 Electron 原生菜单的控制台形态；`--help` 给出端口和可信代理等参数，`--open-browser` 在就绪后打开私密管理 URL，控制台摘要与 `服务器运行信息.txt` 同步记录管理入口、配置和数据路径。浏览器使用 F5、F11、Ctrl+0 完成刷新、全屏和缩放。

### Android、Windows、macOS 与 UI

- Android 与桌面客户端继承全屏零弹窗、弹幕显示、F12/手势消歧、简洁模式、仅聊天、清晰度申请和地址隐私规则；移动端保留至少 48px 的触控目标。
- 本轮保留现有暗色影院色板，新增控件使用现有按钮、输入框、焦点环和危险操作样式，不引入新的前端框架。
- Windows 与 macOS 应用包必须从最终 v2.2.4 Tag 真实重建；macOS 12 项继续由真实 x64/arm64 runner 生成，Windows 不能伪造 DMG 或改名旧包。
- Android `versionName=2.2.4`、`versionCode=20204`；APK 继续包含三个声明 ABI，并由项目发布签名和模拟器安装/启动门禁验证。

## 普通用户怎么选

- 只加入别人服务器：Windows 体验版、Android APK、macOS 客户端或浏览器。
- Windows 自己开房：标准服务器便携版；需要跨平台离线下载中心时选择完整安装版或完整便携版。
- Mac 自己开房：按 Intel x64 或 Apple Silicon arm64 选择服务器版；需要离线下载中心时选择完整离线版。
- 源码或独立服务器：安装官方 Node.js 22+；正式桌面包已内置运行时，无需重复安装。
- 只从 [GitHub Release v2.2.4](https://github.com/xuange6610/SyncWatch/releases/tag/v2.2.4) 的真实资产列表下载；若文件名、大小或哈希与 Release 记录不一致，应停止安装并报告，不使用第三方改名包或来源不明文件。

## 跨平台完整套装

完整离线包把同一最终 Tag 真实构建并验证的 Windows 客户端、Android APK、macOS x64/arm64 客户端与服务器 ZIP 放入房主端下载中心。缺少任一平台文件时，Windows/macOS 完整包构建必须失败，不能嵌入旧版本、空文件或占位文件继续发布。

## 一键运行包含什么

Windows 正式服务器包内置 Electron/Node.js 运行时、应用前后端、生产依赖、Socket.IO、FFmpeg、FFprobe 和 Windows cloudflared。启动时初始化数据目录、检查端口、启动 HTTP/WebSocket 服务，并只在服务器窗口显示局域网地址；实际内容由最终成品闭包测试证明。

## macOS

v2.2.4 的客户端、服务器和完整离线版分别提供 Intel x64 与 Apple Silicon arm64 的 DMG/ZIP，共 12 项。它们已由真实 macOS runner 从最终 Tag 构建并完成启动与包闭包验证，没有使用 Windows 产物、改名旧包或只更新应用显示版本替代。签名、公证和 Gatekeeper 状态以最终构建记录为准。

## 架构支持边界

- Windows 桌面：x64；当前不承诺未经完整验证的 32 位桌面组合。
- Android 通用 APK：`armeabi-v7a`、`arm64-v8a`、`x86_64`，以 APK 解包和签名检查为准。
- macOS：Intel x64 与 Apple Silicon arm64；现代 Electron/macOS 不提供 32 位桌面包。
- 独立服务器：以 Node.js 22+ 对目标系统和架构的官方支持为准。
- Android 本机不能直接运行桌面版 cloudflared；手机跨网访问应连接已开启 HTTPS/Tunnel 的 Windows、macOS、Linux 或云服务器。

## cloudflared 独立工具

提供 Windows x64 EXE、Windows x64/x86 MSI、macOS x64/arm64 二进制共 5 项。它们是 Cloudflare 官方工具，用于手工 Tunnel 与诊断，不是 SyncWatch 启动程序；原子发布工作流会核对固定 [Cloudflare 官方 Release](https://github.com/cloudflare/cloudflared/releases/latest) 的来源、平台、架构、大小和 SHA-256。

## Node.js 官方环境包

提供 Windows x64/ARM64 MSI、macOS x64 PKG 和 macOS arm64 tar.gz 共 4 项，供源码和独立服务器使用。它们是 Node.js 官方分发文件，不由 SyncWatch 源码生成；正式桌面包已内置运行时。原子发布工作流会核对 [Node.js 官方下载](https://nodejs.org/en/download) 的固定版本、平台和 SHA-256。

## 首次启动、升级与安全

1. 首次启动使用 `admin` / `admin888` 登录并立即修改默认密码；公网部署前先完成局域网连接测试。
2. 升级前停止旧服务器并备份整个 `SyncWatch同步观影-Data/`，不要只复制 `config.json`。
3. 房间复制/迁移会复制媒体文件，执行前确认目标磁盘空间并保留独立备份；超级管理员覆盖迁移需要明确二次确认。
4. 不公开数据目录、SMTP 密钥、Tunnel 令牌、签名文件、聊天记录、真实 IP 或带权限的房间链接。
5. v2.2.4 Release 已公开且 26+2 文件和哈希均已验证；部署时仍应按资产名和 SHA-256 复核后再升级生产环境。

## 已知限制

1. 当前没有小米 14 / HyperOS 真机安装、后台保活、全屏手势和屏幕共享证据；最终 Android 工作流使用模拟器验收，不能冒充特定真机通过。
2. 房间媒体复制需要源文件仍存在且服务器对目标数据目录有足够空间；跨物理服务器迁移仍应使用停机备份/恢复流程。
3. 普通客户端没有可信公网根地址时不会回退分享 LAN IP；请由服务器管理员配置公网根地址或从当前 HTTPS/Tunnel 页面访问。
4. 全屏零弹窗会延后需要用户确认的清晰度申请，退出全屏后才显示；这用于避免观影中断。
5. Cloudflare Quick Tunnel、家庭上行和 VPN/TUN/Fake-IP 网络没有固定 SLA；默认原画带宽较高，弱网用户可手动选择流畅版。

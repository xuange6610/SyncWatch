# Wiki 完整教程目录

GitHub Wiki 与仓库文档使用同一套内容。下面的页面会复制到仓库 Wiki，并使用仓库中的真实截图作为图文教程。

## Wiki 页面

1. **Home**：项目定位、在线展示入口、下载选择和安全边界。
2. **01-新手快速开始**：从下载、启动、首次登录、改密码到创建房间。
3. **02-管理中心**：房间、成员、聊天、账号、申请、等级、通知、邮件、日志和服务器设置逐按钮说明。
4. **03-成员连接与同步播放**：局域网、公网、客户端、浏览器、Android、视频播放和文本/小说阅读同步。
5. **04-公网访问与 Cloudflare Tunnel**：临时地址、cloudflared、固定域名、诊断和安全注意事项。
6. **05-发布文件与下载**：Release 文件名、平台、架构、校验、体验版和完整包区别。
7. **06-数据结构与备份迁移**：每个数据目录的作用、备份范围、恢复顺序和隐私保护。
8. **07-故障排查**：端口、依赖、APK、EXE、Tunnel、媒体、权限和日志问题。
9. **08-开发与贡献**：项目结构、构建、测试、提交规范、Apache-2.0 和原创署名。
10. **09-技术原理与架构**：启动流程、登录时序、Socket.IO 房间同步、媒体处理、数据持久化、公网隧道、运行环境、组件版本和跨端调用关系。
11. **33-v2.2.2更新公告**：v2.2.2 源码候选相对 v2.2.0 的真实变化、待构建资产和未验证边界。
12. **30-v2.2.0更新公告**：从 v2.1.9 到 v2.2.0 的已发布功能、平台、文档、构建、测试和历史边界。
13. **31-Wiki维护与版本同步**：版本更新后同步版本公告、操作教程、仓库镜像、GitHub Wiki 和 Pages HTML 的固定检查表。

## 版本同步要求

每次版本变更都要更新 `docs/wiki/` 中的版本公告和受影响教程，再把同名 Markdown 同步到 GitHub Wiki，并运行 `node scripts/build-document-guides.js` 更新主要 Pages HTML。完成后运行 `npm run test:repo` 与 `git diff --check`，逐页检查链接、版本号和“未验证”声明。只更新 README 或 Release 正文不算完成 Wiki 更新。

## 图文来源

Wiki 图片统一引用 `docs/screenshots/` 中的已审核截图。新增截图前必须检查：不包含真实姓名、邮箱、访问令牌、私人 IP、房间链接或未授权媒体名称；截图应能证明一个真实功能，而不是只展示装饰界面。
